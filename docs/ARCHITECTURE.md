# mac-gyver 구현 구조

하나의 시나리오 모델을 수동 편집, 미리보기 기록, GUI 실행, 명령줄 실행에서 공유합니다. 실제 기기와 모의 기기는 같은 제스처 인터페이스를 사용하며, 보고서에서 실행 환경을 구분합니다.

## 구성

| 구성 | 역할 |
| --- | --- |
| `models.py` | 버전 1 JSON 검증, 단계·좌표·시간·반복 제한, 저장·복원 |
| `coordinates.py` | 표시 영역 여백을 제거하고 정규화 좌표와 기기 좌표 변환 |
| `recording.py` | 미리보기 입력을 단계로 기록, 동작 사이 대기 계산 |
| `device.py` | Appium XCUITest 연결, 제스처 입력, 화면·요소 조회 |
| 모의 기기 백엔드 | 정해진 사진·상태를 통해 UI와 엔진을 기기 없이 실행 |
| 실행 엔진 | 준비 단계·사전 조건·반복·대기·검사·취소, 결과 집계 |
| `reports.py` | 실행별 JSON·HTML 결과와 PNG 경로 관리 |
| `ui/` | PySide6 창, 미리보기 입력, 단계와 속성 편집, 실행 제어 |
| `__main__.py` | GUI 진입, `--demo`, `--diagnose`, `--run` 명령줄 경로 |

## 시나리오와 좌표

시나리오는 `schema_version: 1`, `setup`, `steps`를 갖습니다. 기록한 시나리오의 `app_bundle_id`는 연결할 때 선택한 대상 앱을 고정하며, 재생 시 다른 앱의 연결 설정이면 시작 전에 중단합니다. 이전 형식에는 이 선택 필드가 없어도 됩니다. 임의 코드를 평가하거나 실행하지 않습니다. JSON의 지원 단계·매개변수 범위·파일 경로를 검증한 뒤 실행합니다. 저장 형식의 기준은 [models.py](../src/mac_gyver/models.py)입니다.

좌표 입력은 화면 내 0~1 범위이며, 미리보기의 letterbox 여백을 터치 영역에 포함하지 않습니다. WDA의 기기 좌표와 스크린샷 픽셀 수는 다를 수 있습니다. 기록한 화면 크기와 방향을 재생 전에 비교하며, 다른 경우 자동으로 추정해 입력하지 않습니다.

UI 요소 대상은 locator와 값을 저장하고 실행할 때 다시 찾습니다. 스크린샷을 보던 시점의 WebElement 참조를 장기간 보관하지 않습니다. 접근성 식별자가 중복되거나 UI 언어가 달라지면 요소 검사기로 선택값을 확인해야 합니다.

## 기록과 명령 직렬화

미리보기에서 확정한 동작을 기기에 전달하고 화면을 갱신한 뒤 다음 입력을 받습니다. 스와이프는 마우스를 놓을 때 경로와 이동 시간을 확정합니다. 첫 버전 경로는 직선입니다.

선택한 경우에만 동작 사이 대기를 기록합니다. 해당 대기는 직전 명령·화면 갱신이 끝난 뒤 입력 가능한 상태에서 보낸 시간입니다. 도구·속성 편집에 걸린 시간은 입력 대기에 섞지 않습니다. 아이폰 본체의 손가락 입력은 녹화하지 않습니다.

기기 명령은 한 세션에서 직렬로 처리합니다. UI 스레드에서 네트워크 응답을 기다리지 않고, 실행 중 편집·수동 입력과 별도 화면 요청이 제스처 순서를 흐트러뜨리지 않게 제어합니다.

## 타이밍과 취소

- `press_duration_ms`: 이동하기 전 누르는 시간.
- `move_duration_ms`: 직선 이동의 목표 시간.
- `hold_duration_ms`: 끝점에서 손가락을 떼기 전 유지 시간.
- `after_delay_ms`: 기기 명령이 반환된 후 기다리는 시간.
- `between_iterations_ms`: 반복 회차 사이에 추가하는 대기.

스와이프·드래그의 이동 시간은 W3C Actions의 포인터 이동으로 표현합니다. `dragFromToForDuration`의 duration을 이동 시간으로 오해하지 않습니다. 핀치·회전은 backend가 지원하는 제스처 매개변수로 변환합니다.

기다리는 동안 일시정지·중단을 확인하고, 중단 이후 새 제스처를 전송하지 않습니다. 이미 Appium/WDA에 전달한 명령은 완료되거나 제한 시간이 지날 때까지 남을 수 있습니다. 명령 실패 후 자동 재시도는 하지 않습니다. 실행을 다시 시작하면 기본적으로 시작 화면 검사 후 준비 단계부터 실행합니다. GUI의 `준비 단계 포함` 또는 CLI의 `--skip-setup`으로 준비 단계 실행 여부를 지정할 수 있으며, 시작 화면 검사는 유지합니다.

보고서 시간은 호스트에서 관측한 시간입니다. 밀리초 수준 입력 시각 보장, 터치 latency, FPS 측정으로 해석하지 않습니다.

## 판정

`wait_element`는 요소가 표시되거나 사라질 때까지 대기합니다. `assert_element`는 현재 요소 상태를 검사합니다. `assert_image`는 기준 이미지와 같은 크기의 화면에서 지정한 영역의 평균 RGB 절대 차이를 0~1 값으로 비교합니다. `tolerance`는 해당 평균 차이의 경계입니다.

이미지 파일 크기가 다르면 실패로 처리하고 자동 리사이즈해 차이를 숨기지 않습니다. 기준 이미지는 시나리오 파일을 기준으로 한 상대 경로이며, 시나리오 폴더 밖으로 나가는 경로는 허용하지 않습니다. 시간·도구 모음 등 불필요하게 변하는 영역을 비교에서 제외하세요. 단순한 픽셀 차이만으로 다른 사진의 의미적 동일성을 판단하지 않습니다.

검사 통과와 명령 실행 완료를 구분합니다. 검사 없는 명령 실행은 `검사 없음`이며, 준비 단계의 검사만으로 본 테스트 동작을 검증했다고 보지 않습니다. 모의 기기의 통과는 UI와 엔진의 시뮬레이션 결과입니다.

## 저장과 패키징

기본 데이터 폴더는 macOS의 `~/Library/Application Support/mac-gyver`입니다. GUI 설정은 `config.json`, 실행 보고서는 `reports`, 임시 시나리오는 `drafts` 아래에 저장합니다. 개발·검증 용도로 `MAC_GYVER_DATA_DIR`을 지정할 수 있습니다. 사용자가 시나리오를 저장하면 기준 이미지는 `<시나리오이름>.assets` 폴더로 복사되고 JSON 상대 경로가 갱신됩니다. JSON과 해당 폴더를 함께 관리해야 합니다.

`Start.command`는 실행 파일 위치를 기준으로 프로젝트를 찾고 `.venv`를 준비합니다. 초기 설치 후에는 직접 의존성 버전과 manifest 변경을 확인해 필요할 때만 다시 설치합니다. Python·Xcode·Node는 설치하지 않습니다.

Appium은 별도 터미널에서 `.tools/` 아래의 고정 버전을 실행합니다. 기본 주소는 localhost이며 서버 로그를 그 터미널에서 확인할 수 있습니다. 앱의 백엔드 코드를 frozen `.app` 안에서도 동일하게 가져오도록 PyInstaller 진입점은 절대 import를 사용합니다. 사용자 데이터와 결과는 `.app` 내부나 현재 작업 디렉터리에 의존하지 않습니다.

## 검증 범위

자동 검증은 좌표 변환, 입력 검증, 기록·복원, 엔진 반복과 취소, 오류 분류, 보고서 및 모의 기기 흐름을 대상으로 합니다. macOS UI 실행, WDA 서명과 실기기 연결, 실제 제스처, `.app` 배포는 별도 실기기 확인이 필요합니다. [실기기 확인표](SETUP_MAC.md#7-실기기-수동-검증-기록)
