# iPhone 제스처 자동 테스트 앱 구현 계획

작성일: 2026-09-15  
상태: 구현 전 계획. 사용자가 맥 PC에 개발자 모드로 연결한 아이폰을 사용한다고 확인했다. USB 연결을 첫 버전의 기준으로 삼는다.

실제 아이폰의 사진 앱을 열고, 사진 선택·좌우 넘기기·확대/축소를 지정한 시간과 순서에 따라 반복하는 데스크톱 앱을 만든다. 사용자는 화면에서 테스트를 편집하고 실행 결과와 스크린샷을 확인한다.

## 1. 요구사항과 기본 결정

| 구분 | 내용 |
| --- | --- |
| 사용자 요청 | 실제 아이폰에서 사진 선택 및 좌우 넘기기 자동화 |
| 사용자 요청 | 터치 제스처, 타이밍, 딜레이 설정 |
| 이번 산출물 | 반복할 동작의 입력·기록·편집 방식을 포함한 구현 계획서 |
| 확정 실행 환경 | 맥 PC + 개발자 모드를 활성화한 아이폰 |
| 연결 기본값 | USB로 연결한 아이폰 1대 |
| 조작 방식 | 맥 앱의 아이폰 화면 미리보기에서 동작 입력·실행·기록, 한국어 화면에서 편집·반복 실행 |
| 첫 대상 | 기본 사진 앱. 다른 앱은 대상 앱 프로필을 추가할 수 있도록 구조화 |
| 저장 방식 | 테스트 시나리오는 JSON, 실행 결과는 JSON·HTML·PNG로 로컬 저장 |
| 미확인 사항 | 아이폰 모델 및 iOS 버전, macOS/Xcode 버전, WDA 서명 환경 |

초기 설정에는 컴퓨터 신뢰, 개발자 모드, UI Automation 설정 및 WebDriverAgent(WDA)의 서명·설치가 필요하다. 이 과정 중 아이폰에서 해야 하는 조작은 앱의 연결 안내에 구체적으로 표시한다. [Appium 기기 설정](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/device-setup/)

첫 버전은 확정된 맥 환경에 집중한다. macOS와 iOS 버전에 맞는 Xcode·Appium 조합을 첫 실행 진단에서 확인한다. [Appium 호환성 기준](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/system-requirements/)

## 2. 사용자 흐름과 화면

1. 앱을 실행하고 연결 진단을 완료한다.
2. 연결된 아이폰과 대상 앱을 선택한다.
3. `기록 시작`을 누르고 아이폰 화면 미리보기에서 반복할 동작을 수행한다.
4. 동작이 실제 아이폰에서 실행되고 단계 목록에 쌓이는 것을 확인한다.
5. `기록 종료` 후 각 단계의 시간·대기·검사 조건을 편집한다.
6. 반복할 연속 구간을 선택하고 횟수와 회차 사이 대기를 설정한다.
7. 한 회 실행으로 검증한 뒤 전체 반복을 시작한다.
8. 결과에서 실패한 단계, 오류 원인, 스크린샷을 확인한다.

| 화면 영역 | 기능 |
| --- | --- |
| 연결 영역 | 기기 정보, 대상 앱, 연결 상태, 진단 결과 |
| 화면 미리보기 | 스크린샷 갱신, 동작 도구 선택, 클릭·드래그 입력, UI 요소 선택 |
| 기록·단계 목록 | 기록 시작·종료, 단계 추가·복제·삭제·순서 변경, 실행 단계 강조 |
| 속성 편집 | 좌표·누르는 시간·이동 시간·대기·검사 조건 설정 |
| 실행 영역 | 한 단계 실행, 전체 실행, 일시정지·재개·중단, 반복 횟수 |
| 결과 영역 | 실행 상태, 단계별 소요 시간, 오류, 스크린샷 및 보고서 열기 |

미리보기는 화면 캡처를 갱신하는 방식으로 시작한다. 입력한 동작의 위치와 경로를 미리보기에 겹쳐 표시한다. 실제 아이폰의 응답을 받은 뒤 화면을 갱신하므로 영상 미러링과 같은 지연 없는 조작을 전제로 하지 않는다.

### 2.1. 반복할 동작은 어떻게 입력하는가

주 입력 방식은 **미리보기에서 실행하며 기록**이다. 맥 앱에서 입력을 받아 Appium 명령으로 변환하고, 실제 아이폰에 전달한 명령과 설정값을 단계로 저장한다. 기본 사진 앱에서도 사용할 수 있도록 구성한다.

| 하고 싶은 동작 | 맥 앱에서 입력하는 방법 | 기록하는 값 |
| --- | --- | --- |
| 사진 선택 | `탭` 도구를 선택한 상태에서 미리보기의 사진을 클릭 | 대상 요소 또는 정규화된 좌표 |
| 좌우 넘기기 | `스와이프` 도구에서 시작점부터 끝점까지 마우스로 드래그 | 두 지점과 마우스 이동 시간 |
| 길게 누르기 | `길게 누르기` 도구에서 시간을 입력하고 위치 클릭 | 대상과 누르는 시간 |
| 더블탭 | `더블탭` 도구에서 위치 클릭 | 대상과 더블탭 동작 |
| 누른 뒤 끌기 | `드래그` 도구에서 경로 지정 후 누름·이동·끝점 유지 시간 입력 | 각 시간과 시작·끝점 |
| 확대·축소 | `확대/축소` 도구에서 대상 영역과 배율·속도 지정 | 대상, 배율, 속도 |
| 두 손가락 회전 | `회전` 도구에서 대상과 각도·속도 지정 | 대상, 각도, 속도 |
| 잠시 기다리기 | `대기 추가`에서 500ms, 1초 등 입력 | 고정 대기 시간 |
| 화면이 준비될 때까지 기다리기 | `조건 대기`에서 요소와 제한 시간 선택 | 표시·사라짐 조건 및 제한 시간 |
| 동작 확인 | `검사 추가`에서 요소 또는 이미지 비교 영역 지정 | 기대 상태 또는 기준 이미지 |

제스처 도구를 명시적으로 선택하게 해서 클릭을 더블탭·길게 누르기로 잘못 해석하지 않도록 한다. 첫 버전의 스와이프·드래그는 두 점 사이의 직선 경로를 기록한다. 손으로 그린 곡선을 그대로 재생하는 기능은 이후 확장한다.

스와이프는 마우스를 놓을 때 시작점·끝점·지속 시간을 확정하고 아이폰에 전달한다. 확대·축소와 회전은 마우스 하나로 설정할 수 있는 전용 편집 창을 제공한다. 맥 트랙패드의 핀치 제스처를 직접 전달하는 기능은 첫 버전의 필수 조건으로 두지 않는다.

기록 중에는 한 동작씩 실행하고 화면 갱신 후 다음 입력을 받는다. 실행 오류가 발생하면 해당 단계를 오류 표시와 함께 남기고 기록을 일시정지한다. 미리보기의 이전 화면에 연속으로 입력한 클릭을 쌓아두지 않는다.

이 기록 방식의 수집 대상은 **맥 앱을 통해 입력한 동작**이다. 아이폰 본체를 손으로 직접 조작한 동작을 수집하는 기능은 포함하지 않으며 기록 화면에 이를 안내한다. 본체에서 시작 화면을 준비한 경우에는 맥 앱의 `화면 새로고침` 후 기록한다.

### 2.2. 기록한 시간과 사용자가 지정한 시간을 어떻게 구분하는가

기본값은 단계마다 명시적인 대기를 편집하는 방식이다. 마우스 드래그 중의 이동 시간은 자동 입력하고 사용자가 나중에 바꿀 수 있게 한다. 녹화 버튼을 누른 이후의 모든 시간을 그대로 테스트 시간으로 사용하지 않는다.

선택 기능인 `동작 사이 대기도 기록`을 켜면 이전 동작의 실행·화면 갱신이 끝나 입력 가능한 상태가 된 때부터 다음 입력까지를 대기로 기록한다. 이 값은 아이폰 본체의 실제 터치 간격이 아니라 **기록 화면에서 사용자가 기다린 시간**임을 표시한다. 도구 선택·속성 편집에 걸린 시간은 포함하지 않는다.

기록을 종료하면 사용자는 대기를 개별 수정하거나 선택한 단계 전체에 같은 값을 적용할 수 있다. 예를 들어 좌우 넘기기 20개의 동작 후 대기를 한 번에 1초로 바꾼다.

### 2.3. 반복 구간은 어떻게 지정하는가

단계 목록에서 연속된 단계를 선택하고 `반복으로 묶기`를 누른다. 반복 횟수와 회차 사이 대기를 입력한다. 첫 버전은 한 단계의 반복 그룹만 지원하며 그룹 안에 또 다른 반복 그룹을 넣지 않는다.

예를 들어 사진 앱 열기와 사진 선택을 준비 단계로 두고, `왼쪽 넘기기 → 대기 → 오른쪽 넘기기 → 대기` 네 단계만 묶어 100회 반복한다. 마지막 사진에서 계속 왼쪽으로 넘기는 시나리오는 테스트 사진 수를 넘어가지 않도록 구성하고, 사진 변경 검사 실패 시 기본적으로 중단한다.

기본 오류 정책은 `실패 시 중단`이다. 일시정지는 현재 기기 명령이 끝난 뒤 다음 단계 직전에 적용하며, 정지 후 다시 실행할 때에는 준비 단계부터 시작할지 선택하게 한다. 실패한 스와이프를 자동으로 재시도해 사진이 두 장 넘어가는 상황은 만들지 않는다.

### 2.4. 수동 추가와 파일 입력

기록 없이 `단계 추가`로 시나리오를 만들 수도 있다. 만들어진 시나리오는 JSON으로 저장하고 다시 불러온다. 고급 사용자용 JSON 편집 탭을 제공하되, 불러오기 시 지원 단계·시간·좌표·반복 횟수를 검증한다. 첫 버전에서 임의 Python 코드를 실행하는 입력은 제공하지 않는다.

아래는 저장 구조의 예시이며 실제 사진 앱에 적용하기 전 대상 좌표를 지정한다. 좌표는 표시 화면 내부의 0~1 비율이고 방향·화면 크기 정보는 기기 프로필에 별도로 보존한다.

```json
{
  "schema_version": 1,
  "name": "사진 왕복 넘기기",
  "app_profile": "photos",
  "device_profile": "my_iphone_portrait",
  "on_failure": "stop",
  "setup": [
    {"type": "activate_app"},
    {
      "type": "tap",
      "target": {"mode": "normalized", "x": 0.25, "y": 0.35},
      "after_delay_ms": 1000
    }
  ],
  "steps": [
    {
      "type": "repeat",
      "count": 100,
      "between_iterations_ms": 500,
      "steps": [
        {
          "type": "swipe",
          "from": {"x": 0.8, "y": 0.5},
          "to": {"x": 0.2, "y": 0.5},
          "move_duration_ms": 300,
          "after_delay_ms": 1000
        },
        {
          "type": "swipe",
          "from": {"x": 0.2, "y": 0.5},
          "to": {"x": 0.8, "y": 0.5},
          "move_duration_ms": 300,
          "after_delay_ms": 1000
        }
      ]
    }
  ]
}
```

이 JSON 예시는 동작 입력과 반복 구조를 설명하기 위한 것이다. 앨범 진입과 대상 사진 지정은 사용자 환경에 맞게 기록해야 하고, 검사를 추가하지 않은 실행은 `검사 없음`으로 표시한다.

## 3. 첫 버전의 테스트 단계

| 단계 | 사용자가 설정할 값 |
| --- | --- |
| 앱 열기 | 대상 앱 프로필 |
| 탭 | 대상 요소 또는 위치 |
| 더블탭 | 대상 요소 또는 위치 |
| 길게 누르기 | 대상, 누르는 시간 |
| 스와이프 | 시작점·끝점, 이동 시간 |
| 드래그 | 시작점·끝점, 이동 전 누르는 시간, 이동 시간, 끝점에서 유지 시간 |
| 확대·축소 | 대상, 배율, 제스처 속도 |
| 두 손가락 회전 | 대상, 회전 각도, 제스처 속도 |
| 고정 대기 | 대기 시간 |
| 조건 대기 | 요소 표시·사라짐, 최대 대기 시간 |
| 결과 검사 | 요소 상태 또는 사용자가 지정한 이미지 영역 비교 |
| 스크린샷 | 저장 이름 |
| 반복 | 전체 시나리오 또는 선택한 연속 구간의 반복 횟수 |

Appium의 기본 제스처와 W3C Actions를 사용한다. 제스처 입력 지원과 대상 앱의 기능 지원은 별개이므로, 사진 앱이 현재 화면에서 처리하지 않는 제스처는 입력 성공만으로 기능 통과로 판정하지 않는다. [Appium 제스처](https://appium.github.io/appium-xcuitest-driver/latest/guides/gestures/)

임의 곡선 경로 편집, 복잡한 조건 분기, 여러 기기 동시 실행, 장시간 영상 녹화는 첫 버전 이후 확장 대상으로 둔다.

## 4. 타이밍 설계

시간 설정은 밀리초(ms)를 기본으로 표시하고 초(s) 환산을 함께 제공한다. 다음 시간을 독립적으로 관리한다.

| 시간 | 의미 |
| --- | --- |
| 누르는 시간 | 손가락을 내린 뒤 이동을 시작하기 전까지 |
| 이동 시간 | 시작점에서 끝점까지 이동하는 목표 시간 |
| 끝점 유지 시간 | 이동을 마친 뒤 손가락을 떼기 전까지 |
| 동작 후 대기 | 해당 명령이 반환된 뒤 다음 단계를 시작하기 전까지 |
| 조건 제한 시간 | 조건 충족을 기다릴 최대 시간 |

이동 시간은 W3C 포인터 동작의 duration으로 구성한다. Appium `dragFromToForDuration`의 duration은 이동 전 누르는 시간이므로, 이를 이동 시간으로 사용하지 않는다. 확대·축소와 회전은 해당 API의 배율·각도 및 속도 단위를 따른다. [Appium 제스처 매개변수](https://appium.github.io/appium-xcuitest-driver/latest/reference/execute-methods/#mobile-dragfromtoforduration)

고정 시간 대기와 상태 확인 대기를 모두 지원한다. 앱이 준비될 때까지 기다리는 기본 동작을 유지하며, 애니메이션 중 연속 입력 등 별도의 목적이 생기면 해당 시나리오에 맞춰 동기화 설정을 검토한다.

실제 터치가 발생한 시각이나 화면 반응 지연을 밀리초 단위로 보장하지 않는다. 보고서에는 설정값과 호스트에서 관측한 명령 시작·종료 시간을 기록하며, 이를 실제 터치 지연이나 렌더링 성능으로 표시하지 않는다. 짧은 동작의 간격이 중요하면 하나의 W3C 동작 묶음으로 구성하고 중간 캡처를 넣지 않는다.

## 5. 사진과 좌표를 안정적으로 찾는 방법

- UI 요소의 접근성 식별자·속성을 우선 사용한다. 찾을 수 없는 위치는 사용자가 미리보기에서 좌표로 지정한다.
- 기록 시작 시 기준 화면 또는 기준 요소를 저장한다. 재생 시작 시 이 상태를 확인하고, 사진 앱이 이전 실행의 다른 화면에 머물러 있으면 시작 화면을 준비하도록 안내한다. 앱을 여는 것만으로 항상 같은 앨범 화면에 도달한다고 가정하지 않는다.
- 사진 앱의 언어·iOS 버전에 따른 화면 차이는 앱 프로필과 최초 대상 지정 과정으로 처리한다. 모든 버전에서 동일한 버튼 이름이나 썸네일 순서를 가정하지 않는다.
- 화면 미리보기의 확대·축소 비율과 여백을 제거한 뒤 WDA가 사용하는 좌표계로 변환한다. 스크린샷 픽셀 수와 입력 좌표 크기가 같다고 가정하지 않는다.
- 화면 방향과 크기를 단계에 기록한다. 저장된 조건과 달라지면 실행 전 다시 맞추도록 알리고 잘못된 좌표로 진행하지 않는다.
- 오래된 UI 요소 참조는 실행 시 다시 찾는다. 예상치 못한 팝업은 캡처와 오류 기록을 남기고 중단한다.

테스트 시작 전, 서로 구별되는 정지 사진 최소 3장을 내려받아 둔 전용 앨범을 사용한다. 사진 삭제·공유·편집 동작은 기본 예제에 넣지 않는다.

## 6. 실행 결과 판정

명령이 반환되었다는 사실과 원하는 화면이 표시되었다는 사실을 따로 기록한다.

| 상태 | 판정 기준 |
| --- | --- |
| 통과 | 사용자가 지정한 검사 조건을 모두 만족 |
| 실패 | 요소 검사 또는 이미지 비교 조건 불만족 |
| 실행 오류 | 연결 끊김, 명령 오류, 제한 시간 초과 |
| 검사 없음 | 동작은 끝났지만 확인 조건을 지정하지 않음 |
| 중단 | 사용자가 실행을 중단함 |

사진 변경 여부는 UI가 제공하는 식별 가능한 정보 또는 선택한 화면 영역의 이미지 비교로 검사한다. 이미지 비교는 기준 이미지와 허용 오차를 지정하고, 시계·도구 모음처럼 바뀌는 영역을 제외한다. 단순한 화면 변화만으로 다른 사진이 열렸다고 확정하지 않는다. 비슷한 사진, Live Photo, 확대 상태 등 판정이 불확실한 경우에는 수동 확인이 필요한 결과로 표시한다.

## 7. 구현 구조

| 구성 요소 | 선택 및 역할 |
| --- | --- |
| 데스크톱 UI | Python + PySide6, 한국어 화면과 미리보기·기록 도구·단계 편집기 |
| 기록기 | 선택한 도구와 마우스 입력을 공통 단계 모델로 변환, 실행 상태·대기 시간 수집 |
| 시나리오 모델 | 버전이 있는 JSON 스키마, 단계 및 매개변수 검증 |
| 실행 엔진 | UI와 분리한 작업 스레드, 순차 실행, 취소·대기·반복 관리 |
| 기기 연결 | Appium Python Client + Appium 서버 + XCUITest Driver |
| 아이폰 측 | 서명된 WDA를 통해 XCTest UI 자동화 실행 |
| 결과 저장 | 실행별 폴더에 JSON 결과, HTML 보고서, PNG 캡처 |

Python·PySide6·Appium·드라이버 버전은 실제 macOS/Xcode/iOS 조합을 확인한 뒤 고정한다. Python UI는 Qt for Python의 공식 배포인 PySide6를 사용한다. [Qt for Python](https://doc.qt.io/qtforpython-6/quickstart.html) [Appium 호환성 기준](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/system-requirements/)

기기 세션당 명령을 직렬화하고 중복 실행을 막는다. 실행 중 미리보기 요청이 명령 대기열을 무한히 늘리지 않도록 캡처 요청을 합친다. 시간 대기는 취소할 수 있게 구현한다. 중단 시 새 명령을 보내지 않으며, 이미 아이폰에 전달된 제스처는 끝날 수 있다는 상태를 화면에 표시한다.

첫 실행 진단은 macOS/Xcode, 의존성, 기기 연결, 개발자 모드, WDA 연결 상태를 가능한 범위에서 확인한다. 자동 확인이 불가능한 설정은 사용자 확인 항목으로 구분한다. 서버는 로컬 연결을 기본으로 하며 사용자 사진과 캡처를 외부로 전송하는 기능을 넣지 않는다.

## 8. 기본 제공 시나리오

| 시나리오 | 실행 내용 | 확인 방법 |
| --- | --- | --- |
| 사진 왕복 넘기기 | 사진 A 열기 → 1초 대기 → 왼쪽으로 300ms 스와이프 → 1초 대기 → 오른쪽으로 300ms 스와이프 | 사진 B 전환과 사진 A 복귀를 지정된 조건으로 확인 |
| 확대·축소 | 사진 열기 → 두 손가락 확대 → 1초 대기 → 축소 | 캡처와 설정된 화면 검사 |
| 길게 누르기 | 지정 위치를 1.5초 누르기 | 예상 메뉴 등 대상 화면의 조건 검사 |
| 반복 실행 | 사진 왕복 넘기기 20회 | 각 회차의 판정과 실패 지점 저장 |

초기 사진 선택은 사용자가 테스트 앨범과 사진을 한 번 지정하면 시나리오에 저장한다. 확대·축소처럼 같은 배율을 역으로 적용해도 원래 화면과 정확히 일치하지 않을 수 있는 단계는 대상 앱에서 복원 동작을 확인한 후 반복 예제에 사용한다.

## 9. 구현 순서와 단계별 완료 기준

| 단계 | 구현 내용 | 완료 기준 |
| --- | --- | --- |
| 1. 연결 및 최소 기능 | 진단, WDA 연결, 사진 앱 열기, 캡처, 탭과 왕복 스와이프 | 실제 아이폰에서 사진 A → B → A 동작을 한 번 실행하고 확인 |
| 2. 실행 엔진 | 시나리오 검증, 대기·반복, 중단, 단계별 결과 | 제한 시간 초과·연결 끊김·중단을 구분하고 다음 명령이 잘못 실행되지 않음 |
| 3. 기록·편집 UI | 화면 미리보기, 도구별 입력 기록, 좌표·요소 선택, 단계 편집과 반복 묶기 | 코드를 수정하지 않고 사진 왕복 동작을 기록·저장·재실행 가능 |
| 4. 제스처와 판정 | 멀티터치, 시간 설정, 조건 대기, 이미지 검사 | 지원 제스처가 실기기에서 동작하고 동작 완료와 검사 통과가 구분됨 |
| 5. 보고서 및 배포 | 결과 열기, 오류 안내, 설치·실행 안내, 앱 패키징 | 전달한 파일로 설치 후 기본 시나리오 실행 및 결과 확인 가능 |

실기기에 접근할 수 없으면 엔진·UI·설치 자료를 준비하되 1단계의 실기기 완료 기준은 미검증으로 남긴다. 모의 기기 테스트나 화면 데모를 실기기 검증으로 표시하지 않는다.

## 10. 검증과 전달물

핵심 자동 검증은 미리보기 크기·여백을 고려한 좌표 변환, 기록한 동작의 저장·복원, 도구 전환에 걸린 시간을 대기에 포함하지 않는 처리, 잘못된 입력 차단, 제한 시간 및 중단 처리, 반복과 결과 집계에 집중한다. 같은 동작을 구현 그대로 되풀이하는 테스트는 추가하지 않는다.

실기기에서는 선택한 아이폰/iOS 조합으로 사진 왕복 20회, 확대·축소, 길게 누르기, 미표시 요소의 제한 시간 초과, 대기 중 중단, 연결 해제를 확인한다. 기기 모델·iOS·Xcode·Appium 버전과 관측 결과를 기록한다. 한 기기의 성공을 모든 아이폰의 호환성으로 확장하지 않는다.

구현 단계의 전달물은 다음과 같다.

- 앱 소스 및 고정된 의존성 목록을 담은 ZIP.
- macOS에서 실행할 `Start.command`와 초기 설치·실행 안내.
- 기본 시나리오 JSON과 결과 보고서 예시.
- macOS `.app` 패키지 생성 절차. 실제 `.app` 생성·실행 확인은 macOS 환경에서 수행하며, 완료 여부를 별도로 명시한다.
- 지원 확인된 환경과 미검증 항목을 기록한 검증 결과.

현재 단계에서는 이 계획서만 작성한다. 앱 구현은 확정된 맥 PC + 개발자 모드 아이폰 환경에서, 사진 왕복 동작을 직접 기록하고 재생하는 기능부터 진행한다.
