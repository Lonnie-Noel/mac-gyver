# Mac 사진 자동화 작업 규칙

- 이 폴더는 Mac의 사진 앱을 직접 조작한다. 아이폰용 WDA/Appium과 별도다.
- 문서 수정, 빌드, 구문 검사 때문에 사진 앱을 조작하거나 앨범 전체 처리를 시작하지 않는다. 실기기/실사진 검증과 일괄 실행은 사용자가 지정한 작업 범위 안에서만 수행한다.
- 기존 대화에서 승인한 작업은 승인 범위를 유지한다. 이미 승인된 작업에 불필요하게 재확인을 요구하지 않는다.
- 기본 입력은 프로젝트의 `InputImages/` 바로 아래 정지 이미지 파일이다. 지원 확장자는 jpg/jpeg/png/heic/heif/tif/tiff이며 파일명 순서로 목록·해시를 확정한다. 하위 폴더·동영상·다중 프레임 이미지는 포함하지 않는다. `--limit`은 가져오기 전에 적용하며 1장 테스트는 첫 파일 한 장만 복사한다.
- 기본 `plan`은 파일시스템만 조회한다. 사진 앱 실행, 권한 요청, 보관함 가져오기 또는 수정 없이 동작해야 한다. 기본 실행은 사진 앱의 일반 격자 화면에서도 시작할 수 있어야 하며 앨범 ID나 열린 사진을 요구하지 않는다.
- 입력 원본은 읽기 전용으로 취급한다. SHA-256을 확인하고 원본 바이트를 시스템 사진 보관함에 복사한다. 매 실행마다 `MacGyver InputImages <ISO 시각>` 전용 앨범과 새 복사본을 만든다. 기존 사진을 이름만 보고 재사용하거나 원본 파일을 이동·삭제·재인코딩하지 않는다.
- 0.1.6부터 검증한 입력 바이트를 사용자 전용 임시 파일에 기록하고 `PHAssetCreationRequest.addResource(...fileURL:...)`, `shouldMoveFile=false`로 복사한다. 입력 원본 경로를 직접 넘기거나 `data:` 방식으로 되돌리지 않는다. PhotoKit 완료 콜백까지 임시 파일을 유지하고 정상 반환·오류 시 정리한다. 복사 후 원본 리소스의 바이트 수·SHA-256이 입력과 정확히 같아야 편집으로 진행한다. 불일치를 픽셀 유사도·파일명·크기만으로 대체 승인하지 않는다.
- 새 입력 가져오기는 `input-images-file-resource-v1` capability가 있는 도우미가 필요하다. 이전 앱이 실행 중이면 새 복사본을 만들기 전에 재빌드 안내로 중단한다. 기존 미완료 편집의 복구 경로는 이 검사로 막지 않는다.
- 새 앨범과 복사본은 처리 후에도 사진 앱에 남으며 iCloud 사진을 쓰면 동기화될 수 있음을 문서에 설명한다. 반복 실행은 새 복사본을 만들며 이전 결과를 자동으로 건너뛰거나 가져오기를 자동 재개하지 않는다.
- 가져오기 일부가 성공한 뒤 실패·중지할 수 있다. `import.json`과 도우미의 의도·정확한 사진 ID 기록을 보존하며 결과가 불확실한 요청을 자동 재전송하지 않는다. `recover`는 `pending-edit.json`의 미완료 편집만 복구하고 가져오기를 재개하지 않는다.
- 기존 앨범 처리는 명시적인 `--album-id` 옵션에서만 활성화한다. 기본 실행에서는 이전 `config.json`의 `albumId`를 무시한다. 기존 앨범 모드는 그 앨범의 사진 한 장을 연 상태에서 시작하는 기존 흐름을 유지한다.
- 기존 편집이 있는 사진은 건너뛴다. 원본으로 복귀는 이전 편집을 모두 지우므로 마지막 Reframe만 취소하는 수단으로 쓰지 않는다.
- 편집 저장 후 JPEG 내보내기와 검증을 마친 뒤 원본으로 복귀한다. 미완료 편집 기록을 지우거나 성공으로 간주하지 않는다. 복구할 때는 기록의 사진 식별자를 다시 확인한다.
- 사진 라이브러리 데이터베이스를 직접 수정하지 않는다. Photos UI/Apple Events/PhotoKit이 제공하는 동작만 사용한다.
- `artifacts/pending-edit.json`이 있으면 도우미 앱을 다시 빌드하지 않는다. 먼저 기존 앱으로 복구한다. 실행 중 자동 빌드하지 않는다.
- 앨범 ID와 사진 ID를 기준으로 작업한다. 가져온 정확한 ID 집합이 Apple Events로 확인한 해당 앨범의 ID 집합과 같아야 한다. 앨범 표시 순서로 원본 파일과 사진을 짝짓지 말고, 가져오기 응답의 정확한 ID를 입력 파일 순서로 처리한다. 사진 앱과 시스템 사진 보관함의 식별자가 일치하지 않으면 중지하며 보관함을 자동 전환하지 않는다.
- Photos의 `selection`은 다시 조회할 수 없는 내부 앨범을 포함한 객체 참조를 반환할 수 있다. 선택 descriptor에서 media item의 문자열 unique ID를 읽고 보관함 최상위에서 같은 전체 ID를 재조회한다. 이름·인덱스 참조, 중복 ID, 잘린 ID나 파일명으로 대체하지 않는다. AppleScript 반복 변수는 `contents of`로 값을 풀어 속성을 읽는다.
- 권한 설정을 우회하거나 자동으로 보안 설정을 바꾸지 않는다. 사용자가 macOS 설정에서 도우미 앱에 필요한 권한을 부여한다.
- 0.1.5의 권한 요청은 손쉬운 사용·화면 기록·사진 전체 접근·자동화 → 사진을 각각 분리한다. 각 설정 열기와 현재 실행 중인 앱의 Finder 위치 확인을 제공한다. 이전 거부로 요청 팝업이 다시 나오지 않을 수 있으므로 화면 기록 설정에서 앱을 켜거나 `+`로 현재 앱을 추가하는 경로를 안내한다. 화면 기록 설정 변경 후에는 도우미 재시작이 필요할 수 있다.
- 0.1.8부터 권한 요청 버튼은 요청 API만 호출하고 시스템 설정을 추가로 자동 열지 않는다. OS 안내창과 별도 설정 창이 동시에 열리는 것을 방지하기 위한 구분이다. 팝업이 없거나 사용자가 설정을 바꾸려는 경우 전용 ‘설정 열기’ 버튼을 사용한다.
- `이 앱 권한 초기화 후 종료`를 사용자가 명시적으로 실행한 경우에만 `/usr/bin/tccutil reset`을 허용한다. 대상은 `local.macgyver.photosautomation`의 `Accessibility`, `ScreenCapture`, `Photos`, `AppleEvents` 네 항목으로 고정하며 다른 앱이나 전체 권한으로 범위를 넓히지 않는다. 빌드·백그라운드 실행·일반 권한 요청에서 자동 초기화하지 않는다. 초기화는 승인·거부 기록을 재설정할 뿐 권한 자동 승인이나 시스템 설정 목록 항목 삭제를 보장하지 않는다.
- 네 권한 초기화가 모두 성공하면 도우미를 종료한다. 일부 실패는 항목별로 알리고 사용자가 종료·재시작하도록 한다. 초기화 후에는 같은 프로세스에서 권한을 재요청하지 않는다. 사용자가 설정 커맨드로 다시 시작하고 네 권한을 각각 승인한다.
- 권한 요청·초기화 전에 도우미 처리 상태, 프로젝트의 `pending-edit.json`·`active-run.json`, 공유 실행 잠금과 이전 프로젝트의 미완료 편집을 확인한다. 작업 중이거나 상태가 불명확하면 차단한다. 중단된 편집의 복구에 필요한 권한 요청·설정 열기는 허용하지만 미완료 편집이 있으면 초기화는 차단한다. 권한 초기화를 위해 작업·복구 기록을 삭제하지 않는다.
- AX 조회의 일반 실패 `-25200`은 선택 속성인 `AXSubrole`·`AXDescription`·`AXValue`에서만 생략한다. 누락 속성으로 selector를 임의 보완하거나 다른 버튼을 추정해 클릭하지 않는다. 필수 역할·활성 상태·좌표·크기·트리 실패 및 권한·통신 오류는 계속 중단한다. 화면 전환 중 `snapshot`의 `AX_READ_FAILED: AX속성 조회 실패: -25202`에 한해서만 최대 3회 새 트리를 조회한다. 부분 트리는 버리고 입력 동작은 재전송하지 않는다. 재조회 결과도 완전성·전면·대화상자 검사를 통과해야 한다.
- `InputImages/`의 실제 사진, 캡처, 편집·가져오기 기록, `artifacts/`, `config.json`, `logs/`는 커밋하지 않는다. 입력 폴더 사용 안내만 배포한다.
- 소스/오프라인 검사와 실제 사진을 사용한 검증을 구분해 보고한다. 검증하지 않은 UI 흐름을 성공했다고 기록하지 않는다.
- 2026-09-21 후속 스크립트는 가져오기 검증을 통과한 같은 사진 사본 한 장의 Reframe→두 캡처→JPEG 저장·검증→원본 복귀·해시 일치를 실제로 확인했다. 이 결과를 다른 Mac·사진이나 앨범 전체의 검증으로 확대하지 않는다.

- 0.1.9 이후 스크립트의 편집·완료 전환은 버튼을 한 번만 요청한다. 정확히 `AX_PRESS_FAILED: AXPress 실패: -25205`가 반환된 경우에만 최대 5초 동안 읽기 전용으로 같은 사진 ID·파일명, 앱 PID·창, 전면 상태와 예상 편집·보기 화면 전환을 확인한다. 확인한 오류는 `editConfirmation`·`doneConfirmation`·`recoveryDoneConfirmation`에 기록하며 버튼을 재전송하지 않는다. 다른 오류와 다른 버튼 동작에는 적용하지 않는다.

- 도구 화면의 프레임 재설정 진입 버튼(`AXTitle`)과 모달의 생성 버튼(`AXDescription`)을 구분한다. 드래그 전에 모달의 회전·패닝·수평·확대 값과 초기 상태를 확인하고, 드래그 뒤 실제 값 변화를 확인한 후 캡처·생성한다. 안내 문구만으로 준비 상태를 추정하지 않는다.
