# Mac 사진 앱 자동화

`InputImages/`에 넣은 사진을 Mac 사진 앱의 새 작업 앨범으로 복사하고, Reframe 적용 → 화면 캡처·JPEG 저장 → 원본 복귀를 순서대로 실행하는 로컬 도구입니다. 기본 실행에는 앨범 ID 입력이나 설정 파일 편집이 필요하지 않습니다. 아이폰 연결, Appium, WDA와 아이폰용 프로비저닝도 필요하지 않습니다.

## 준비

- Reframe을 지원하는 macOS 27의 사진 앱과 Apple Intelligence 설정이 필요합니다. 실제 화면에 `편집 → 도구 → 프레임 재설정`이 있어야 합니다. 언어·지역·사용량에 따라 기능 사용이 제한될 수 있습니다.
- Node.js **22.12 이상**과 Xcode 개발 도구가 필요합니다. Node.js 26.9.0도 허용하며, 22 버전으로 낮출 필요가 없습니다. npm 패키지 의존성은 없습니다.
- 작업할 보관함을 **시스템 사진 보관함**으로 지정하고 사진 앱에서 열어 둡니다. PhotoKit이 읽는 시스템 보관함과 사진 앱의 항목 ID가 일치하지 않으면 중지합니다.
- 사진 앱은 일반 격자 화면으로 열어 두면 됩니다. 시작할 사진을 미리 크게 열 필요는 없습니다. 자동화가 작업 사진을 열고 전면으로 가져옵니다. 화면 잠금을 해제하고, 처리 중 다른 창을 띄우거나 마우스·키보드로 사진 앱을 조작하지 않습니다.

다음 네 권한은 `Mac 사진 자동화` 도우미에 부여합니다. macOS에 따라 표시 이름이 `MacPhotosBridge`일 수 있습니다.

| 권한 | 용도 |
| --- | --- |
| 손쉬운 사용 | 사진 앱의 버튼·메뉴·드래그 조작 |
| 화면 및 시스템 오디오 기록의 화면 기록 | 사진 앱 창 캡처 |
| 자동화 → 사진 | Apple Events로 사진 앱의 앨범·항목 제어 |
| 사진 → 전체 접근 | 입력 사진 복사·작업 앨범 생성, 사진 ID와 편집 상태 확인·결과 내보내기 |

설정 명령은 도우미의 설정 창을 엽니다. **손쉬운 사용 요청**, **화면 기록 요청**, **사진 전체 접근 요청**, **자동화 → 사진 요청**을 하나씩 눌러 승인합니다. 각 권한 옆의 **설정 열기** 버튼으로 해당 macOS 설정도 바로 열 수 있습니다. 사진 권한은 제한된 사진 선택이 아닌 전체 접근을 허용해야 합니다. 자동화 요청은 사진 앱의 선택 항목을 조회하여 권한을 요청하며 사진을 변경하지 않습니다.

단순 빌드나 백그라운드 실행은 권한을 자동 요청하거나 초기화하지 않습니다. 일반 권한 요청 버튼도 기존 허용 기록을 지우지 않습니다. 권한은 `시스템 설정 → 개인정보 보호 및 보안`에서도 확인할 수 있습니다. 화면 기록 권한 변경 후에는 macOS 안내에 따라 도우미의 **보조 앱 종료** 버튼을 누른 뒤 설정 명령으로 다시 실행해야 할 수 있습니다.

## 처음 설정하기

1. **`Mac 사진 자동화 설정.command`**를 실행합니다. 도우미가 꺼져 있으면 빌드 후 설정 창을 열고, 이미 실행 중이면 빌드 없이 기존 설정 창을 다시 엽니다.
2. 도우미 설정 창에서 위 네 권한을 **각각 요청**하고 부여합니다. **상태 새로고침**으로 네 항목의 상태를 확인합니다.
3. 이 폴더의 **`InputImages/`에 처리할 사진 파일을 넣습니다.** 사진 앱은 시스템 사진 보관함의 일반 보기 화면으로 열어 둡니다.
4. 터미널에서 입력 목록과 실행 환경을 확인합니다. 아래 경로는 실제 프로젝트 위치로 바꾸세요.

   ```bash
   cd /path/to/MacGyver/macos-automation
   node scripts/run.mjs plan
   node scripts/run.mjs check
   ```

기본 `plan`은 **파일시스템의 입력 파일과 순서만 조회**합니다. 사진 앱을 열거나 권한을 부여하지 않아도 실행할 수 있으며, 사진을 보관함으로 가져오지 않습니다.

### 화면 기록 요청 창이 뜨지 않을 때

손쉬운 사용을 승인해도 화면 기록은 별도로 승인해야 합니다. **화면 기록 요청**을 누르세요. 이미 허용했거나 이전에 거부한 경우 macOS가 요청 팝업을 다시 표시하지 않을 수 있습니다.

1. **화면 기록 설정 열기**를 눌러 `개인정보 보호 및 보안 → 화면 및 시스템 오디오 기록`을 엽니다.
2. `MacPhotosBridge` 또는 `Mac 사진 자동화`를 켭니다. 목록에 없다면 도우미의 **현재 앱 Finder에서 보기**로 실행 중인 앱 위치를 확인한 뒤, 설정 목록 아래 **+**로 그 `MacPhotosBridge.app`을 추가합니다. 보통 위치는 `macos-automation/build/MacPhotosBridge.app`입니다.
3. 도우미의 **보조 앱 종료**를 누르고 **Mac 사진 자동화 설정.command**를 다시 실행합니다. **상태 새로고침**에서 화면 기록이 허용으로 표시되는지 확인합니다.

추가할 항목은 현재 빌드한 도우미 앱입니다. 화면 기록 목록의 **+**로 앱을 추가하는 절차는 [Apple 화면 기록 권한 안내](https://support.apple.com/guide/mac-help/control-access-to-screen-and-system-audio-recording-mchld6aa7d23/mac)에서도 설명합니다.

### 재빌드 후 기존 권한을 다시 등록하기

0.1.5부터 설정 창의 **이 앱 권한 초기화 후 종료** 버튼으로 이 도우미의 기존 권한 결정을 초기화할 수 있습니다. 새 코드를 적용하려면 먼저 실행 중인 도우미의 **보조 앱 종료**를 누르고 설정 커맨드를 다시 실행해 빌드하세요.

1. 사진 자동화를 종료하고 미완료 편집이 있으면 먼저 복구합니다.
2. 새 설정 창에서 **이 앱 권한 초기화 후 종료**를 누릅니다. 네 권한의 초기화가 모두 성공하면 도우미가 종료됩니다.
3. **Mac 사진 자동화 설정.command**를 다시 실행한 뒤 네 권한 요청 버튼을 하나씩 눌러 승인합니다.
4. 일부 초기화가 실패하면 해당 권한과 오류를 창에 표시합니다. 이 경우 **보조 앱 종료**를 직접 누르고 설정 커맨드로 다시 시작한 뒤 상태를 확인하세요. 앱을 다시 시작하기 전에는 권한을 재요청하지 않습니다.

초기화 대상은 `local.macgyver.photosautomation`의 `Accessibility`, `ScreenCapture`, `Photos`, `AppleEvents` 네 항목으로 고정되어 있습니다. macOS의 `tccutil reset`으로 이 도우미의 승인·거부 기록만 초기화하며, 다른 앱의 권한은 바꾸지 않습니다. **초기화가 새 권한을 자동 승인하지는 않습니다.** 시스템 설정 목록에 표시되는 앱 항목은 남아 있을 수 있으며, 새 요청의 승인과 목록 관리는 macOS에서 처리합니다. [Apple 권한 초기화 안내](https://developer.apple.com/documentation/xcode/resetting-access-to-protected-resources-in-macos).

자동화 실행 중에는 권한 요청과 초기화를 차단합니다. 미완료 편집이 남아 있으면 초기화는 막지만, 복구에 필요한 권한 요청·설정 열기는 허용합니다. 복구 기록을 지우고 초기화를 강행하지 마세요. 빌드할 때마다 초기화하는 방식이 아니라, 재등록이 필요할 때 이 버튼으로 명시적으로 실행하는 방식입니다.

### 입력 사진 준비와 1장 테스트

지원 확장자는 `jpg`, `jpeg`, `png`, `heic`, `heif`, `tif`, `tiff`입니다. `InputImages/` 바로 아래의 파일을 이름순으로 처리하며, 하위 폴더와 동영상은 포함하지 않습니다. 가져오기 단계에서 실제 이미지 데이터가 유효한 단일 프레임 정지 이미지인지도 검사합니다. 확장자가 맞아도 애니메이션·다중 프레임·손상 파일은 처리하지 않습니다.

`plan`으로 대상을 확인한 뒤 처음에는 **`Mac 사진 자동화 1장 테스트.command`**를 실행하거나 아래 명령을 사용합니다. **`--limit 1`은 가져오기 전에 적용**하므로 이름순 첫 파일 한 장만 사진 앱으로 복사하여 테스트합니다.

```bash
node scripts/run.mjs run --limit 1
```

`.command` 실행 파일은 현재 `PATH`의 Node.js를 우선 사용하고, 사용할 수 없으면 일반적인 설치 경로를 확인합니다. 실행 시 선택한 버전과 경로를 표시하며, 기존 Node.js 설치나 시스템 `PATH`를 변경하지 않습니다. 여러 버전 중 하나를 직접 지정하려면 절대 경로를 설정합니다.

```bash
MACGYVER_NODE='/절대/경로/node' './Mac 사진 자동화 1장 테스트.command'
```

직접 지정한 경로가 실행 불가능하거나 지원 범위 밖이면 다른 Node로 바꾸지 않고 오류를 표시합니다. Finder와 터미널은 `PATH`가 다를 수 있으므로 출력된 실행 경로로 실제 사용 버전을 확인하세요.

기본값으로 실행하면 매번 `MacGyver InputImages <ISO 시각>` 이름의 새 앨범을 만들고 입력 원본의 바이트를 복사합니다. `InputImages/`의 파일은 수정하거나 이동하지 않으며 SHA-256으로 확인합니다. 실행이 끝나도 **복사한 사진과 작업 앨범은 사진 앱에 남습니다.** iCloud 사진을 사용하면 새 앨범과 복사본도 동기화될 수 있습니다.

같은 입력으로 다시 실행하면 새 복사본을 만듭니다. 지난 결과를 자동으로 건너뛰거나 이전 가져오기를 이어서 실행하지 않습니다. 드래그·대기 시간 등을 바꾸려는 경우에만 `config.example.json`을 `config.json`으로 복사해 수정하면 됩니다. 설정 파일이 없으면 예제 기본값을 사용합니다.

앨범 복사는 첫 단계입니다. 이후 터미널에 **가져오기 완료 → 사진 열기 → 지정한 사진의 보기 화면 확인 → 원본 사진과 기존 편집 여부 확인 → 편집 시작**이 표시됩니다. 복사한 사진이 보여도 원본 파일 검증이 끝나기 전일 수 있습니다. 더 진행되지 않으면 반복 실행하기 전에 터미널의 마지막 메시지와 오류를 확인하세요. 실행 폴더의 `manifest.json`에는 마지막 도우미 요청(`lastRequest`)과 실패 이유(`error.message`)가 기록됩니다. 이 기록으로 가져오기·사진 열기·원본 검사 중 어느 요청에서 멈췄는지 확인할 수 있습니다.

### 고급 옵션: 기존 사진 앨범 처리

이미 사진 앱에 있는 앨범을 처리할 때는 `--album-id`를 **명시적으로** 지정합니다. 이 모드에서는 앨범 안의 시작할 사진 한 장을 크게 열고, 편집 화면이 아닌 일반 보기 화면에서 시작해야 합니다. 기존 설정 파일의 `albumId` 값은 기본 실행에서 무시합니다.

```bash
node scripts/run.mjs albums
node scripts/run.mjs plan --album-id '<앨범 ID>'
node scripts/run.mjs run --album-id '<앨범 ID>' --limit 1
```

이 고급 `plan`은 기존 앨범을 조회하므로 사진 앱과 관련 권한이 필요합니다. 기존 앨범 모드는 입력 파일을 가져오거나 새 작업 앨범을 만들지 않습니다. 다른 설정 파일은 `--config '/절대/경로/config.json'`으로 지정할 수 있지만, 기존 앨범 모드는 여전히 `--album-id`를 함께 지정해야 켜집니다.

## 실제 처리 순서

1. `InputImages/`의 입력 목록·순서·해시를 확정하고 제한 장수를 적용합니다. 새 작업 앨범으로 사진을 복사한 뒤, PhotoKit이 반환한 정확한 사진 ID가 사진 앱의 해당 앨범에 모두 있는지 확인합니다. 입력 파일 순서로 처리하며 사진 앱의 표시 정렬 순서에 의존하지 않습니다. 기존 앨범 고급 모드는 현재 열린 사진부터 확정 목록을 순회합니다.
2. 사진의 기존 편집 여부를 확인합니다. **이미 편집된 사진은 건너뜁니다.**
3. 사진 열기 → 편집 → 도구 → 프레임 재설정으로 진입합니다.
4. 프리뷰를 조작할 준비가 되었는지 확인합니다.
5. 프리뷰 중심에서 왼쪽 아래 45도 방향으로 드래그합니다. 기본 이동 거리는 프리뷰 짧은 변 길이의 절반입니다. **드래그 후 프리뷰 화면을 캡처**합니다.
6. 프레임 재설정을 눌러 결과를 생성합니다. 이때부터 기본 최소 25초를 기다리고, 처리 중 표시가 사라졌으며 저장 버튼이 활성화되었는지 확인합니다. 제한 시간 안에 완료되지 않으면 실패로 기록합니다.
7. **저장 전에 결과 화면을 캡처**한 뒤 저장/완료를 누릅니다.
8. 저장된 편집 결과를 전체 크기 JPEG로 내보냅니다. 파일 크기·해시와 이미지 전체 디코딩을 검증합니다.
9. **JPEG 검증 후에만 원본으로 복귀**하고 원본 복원 여부까지 확인합니다. 완료 기록을 남기고 다음 사진으로 이동합니다.

확정한 목록을 모두 처리하면 자동으로 종료합니다. 기본 입력 모드는 검증한 정지 이미지만 가져옵니다. 기존 앨범 모드에서는 이미 편집된 사진과 동영상을 건너뛴 항목으로 기록합니다.

화면 캡처는 사진 앱 **창 전체**를 저장하므로 도구 모음 등 UI가 포함됩니다. 고해상도 사진 결과는 별도 `<원본파일명>-result.jpg`입니다. 창 캡처와 JPEG는 용도가 다릅니다.

Apple의 `원본으로 복귀`는 과거 편집까지 모두 제거합니다. 이 때문에 기존 편집 사진을 제외합니다. 기본 모드는 새로 가져온 복사본을 편집·복귀시키며 `InputImages/`의 원본 파일에는 적용하지 않습니다. 기존 앨범 모드에서 편집·복귀한 사진은 같은 사진이 들어 있는 다른 앨범에도 반영되며, iCloud 사진 사용 시 다른 기기에도 동기화될 수 있습니다.

## 실행·중지·복구

### 설정 창을 다시 열기

`설정 창 숨기기`나 빨간 닫기 버튼은 창만 숨깁니다. 보조 앱은 계속 실행되며 아래 방법으로 설정 창을 다시 열 수 있습니다.

- 메뉴 막대의 **사진 자동화 → 설정 창 열기**
- Finder에서 **MacPhotosBridge.app** 다시 실행
- **Mac 사진 자동화 설정.command** 다시 실행

완전히 종료하려면 설정 창이나 메뉴 막대의 **보조 앱 종료**를 사용합니다. 자동화에서 도우미를 호출할 때는 설정 창을 띄우지 않도록 별도로 처리합니다.

도우미의 Swift 코드가 바뀐 업데이트를 적용할 때는 설정 커맨드로 기존 창을 열고 **보조 앱 종료**를 누른 다음 설정 커맨드를 다시 실행하세요. 실행 중에는 기존 앱의 창을 열 뿐 다시 빌드하지 않습니다. 미완료 편집 기록이 있으면 기존 앱을 열어 복구부터 진행하도록 합니다. JavaScript만 바뀐 업데이트는 다음 스크립트 실행부터 적용되므로 도우미 재빌드나 권한 초기화가 필요하지 않습니다.

| 파일 | 동작 |
| --- | --- |
| `Mac 사진 자동화 설정.command` | 실행 중이면 설정 창 다시 열기, 종료 상태이면 빌드 후 설정 |
| `Mac 사진 자동화 1장 테스트.command` | `InputImages/`의 첫 파일 한 장만 가져와 처리하고 종료 |
| `Mac 사진 자동화 시작.command` | `InputImages/`의 입력 파일을 새 작업 앨범으로 가져와 실행 |
| `Mac 사진 자동화 중지.command` | 진행 중인 작업에 중지 요청 |
| `Mac 사진 자동화 복구.command` | 미완료 편집 기록을 기준으로 복구 |

중지는 즉시 프로세스를 강제 종료하는 명령이 아닙니다. 편집 도중 중단되면 `artifacts/pending-edit.json`에 복구할 사진과 단계가 남습니다. 다음 사진으로 넘어가기 전에 `recover`로 이 상태를 처리합니다. 이 기록이 남아 있으면 앱을 다시 빌드하지 않습니다. 기록 파일을 직접 지우거나 사진을 수동으로 바꾼 뒤 이어서 실행하지 마세요.

가져오기 도중 실패하거나 중지하면 이미 복사된 일부 사진과 작업 앨범이 남을 수 있습니다. 실행 폴더의 `import.json`과 도우미의 가져오기 기록을 보존합니다. 완료 여부가 불분명한 가져오기를 자동 재전송하지 않습니다. **`recover`는 미완료 사진 편집만 복구하며 가져오기를 재개하지 않습니다.** 이후 새로 시작하는 실행은 새 작업 앨범과 복사본을 만듭니다.

```bash
node scripts/run.mjs stop
node scripts/run.mjs recover
```

원본 복귀 전에 내보내기가 실패했으면 결과가 보존되었는지 먼저 확인해야 합니다. 복구는 기록에 있는 사진과 현재 사진이 일치할 때만 진행합니다. 전원이 꺼지거나 앱이 종료되어도 이 기록으로 미완료 편집을 식별할 수 있습니다.

복구를 시작할 때 일반 편집 화면이 남아 있으면 미저장 변경 내용을 구분할 수 없어 멈춥니다. 자동화가 만든 결과라면 `완료`로 저장하고, 불필요한 초안이면 취소하여 일반 사진 보기 화면으로 돌아온 뒤 복구를 다시 실행하세요. 복구는 기록된 사진 한 장만 처리하고 종료합니다.

## 설정

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| `albumId` | `null` | 이전 설정 호환용. 기본 실행에서는 무시하며, 기존 앨범은 명시적인 `--album-id` 옵션으로 지정 |
| `minimumGenerationSeconds` | `25` | Reframe으로 결과 생성을 시작한 뒤 최소 대기 시간(초) |
| `generationTimeoutSeconds` | `300` | 생성 대기 제한 시간(초) |
| `dragRadiusFactor` | `0.5` | 프리뷰 짧은 변 대비 드래그 거리. 최대 `0.65` |
| `dragDurationMs` | `1500` | 드래그에 사용할 시간(밀리초) |
| `pollIntervalMs` | `750` | 상태 확인 간격(밀리초) |

최소 대기 시간만 경과했다고 생성 완료로 간주하지 않습니다. 실제 UI 상태가 준비되어야 다음 단계로 진행합니다. 일일 사용 한도나 네트워크 문제로 생성이 실패할 수 있습니다.

## 저장 위치와 점검 명령

결과는 `artifacts/photos-<ISO 시각>/` 실행 폴더에 모아서 저장합니다. 사진별 하위 폴더를 만들지 않습니다. 각 파일명은 원본 파일명의 확장자를 뺀 이름으로 시작하며, 중복 이름은 구분합니다.

- `<원본파일명>-preview-capture.png`: 드래그 후, 생성 전 프리뷰 창
- `<원본파일명>-result-capture.png`: 생성 후, 저장 전 결과 창
- `<원본파일명>-result.jpg`: 저장한 편집 결과의 전체 크기 JPEG
- `plan.json`: 확정한 입력·앨범·사진 ID와 처리 순서
- `import.json`: 입력 원본과 가져오기 진행·결과 기록
- `manifest.json`: 사진별 처리 결과와 실행 상태
- `.metadata/`: 도우미 요청 등 복구·검증용 세부 기록

입력 사진, 화면과 사진이 담긴 산출물 및 로그는 개인 자료입니다. `InputImages/`의 실제 사진과 `artifacts/`, `logs/`, `config.json`은 Git에서 제외합니다. 도우미 IPC 파일과 가져오기 기록은 사용자 전용 권한(`0700`)의 `~/Library/Application Support/MacGyverMacPhotos/`에 둡니다. 기본 실행은 이 고정 경로를 사용하며, 도우미는 필요한 경우 `--ipc-root`로 별도 절대 경로를 지정할 수 있습니다.

```bash
node scripts/run.mjs check     # 실행 환경과 권한 점검
node scripts/run.mjs inspect   # 현재 UI 상태 확인
node scripts/run.mjs albums    # 기존 앨범을 쓰는 고급 모드용 ID 목록
node scripts/run.mjs plan      # InputImages 파일·순서 조회만 수행, Photos 접근 없음
```

## 도우미 빌드

```bash
npm run build
```

`native/*.swift`를 Swift 5 언어 모드, macOS 15.2 배포 대상으로 빌드합니다. Reframe 동작에는 macOS 27이 필요합니다. 결과 앱은 `build/MacPhotosBridge.app`, 빌드 로그는 `logs/build.log`입니다. 실행 시 자동으로 다시 빌드하지 않습니다. 소스와 서명 설정이 같고 기존 서명이 유효하면 빌드를 건너뜁니다.

`npm run build`는 실행 중인 `MacPhotosBridge`를 덮어쓰지 않습니다. 설정 창이 숨겨져 있다면 **설정 커맨드를 실행해 창을 다시 열고**, **보조 앱 종료**를 누른 뒤 설정 커맨드를 다시 실행하세요. 앱을 교체한 뒤에는 새 도우미를 시작해야 변경 사항이 반영됩니다. 빌드 스크립트가 실행 중인 도우미를 자동으로 종료하지 않습니다.

기본은 로컬 임시 서명(ad hoc)입니다. 변경 후 다시 빌드하면 macOS가 권한 재승인을 요구할 수 있습니다. 이미 보유한 개발 서명 인증서를 사용하려면 다음과 같이 지정합니다. 인증서를 새로 만들거나 계정에 로그인하는 작업은 빌드 스크립트가 수행하지 않습니다.

```bash
MACOS_SIGNING_IDENTITY='Apple Development: <인증서 표시 이름>' npm run build
```

앱의 Bundle ID는 `local.macgyver.photosautomation`으로 고정합니다. 안정된 인증서와 앱 경로를 유지하면 권한 설정 유지에 유리합니다. 앱은 샌드박스 없이 사용자의 로컬 계정에서 실행합니다.

## 검증 범위

0.1.5 이후 JavaScript 수정에서는 사진 열기 요청 직후 Photos가 전면으로 전환되는 시간을 기다리도록 보완했습니다. 이 최초 전환 이후에 다른 앱으로 전환되면 기존처럼 즉시 중단합니다. 복사 이후 단계별 진행 표시와 `manifest.json`의 마지막 요청 기록도 추가했습니다. Node.js 22.23.1에서 **95개 테스트**를 통과했으며, 전면 전환 지연·시간초과·편집 중 전면 이탈을 포함합니다. 이 수정은 도우미 재빌드가 필요하지 않습니다. 사용자가 보고한 복사 후 중단의 실제 실행 기록은 아직 확인하지 못했고, 해당 문제의 해결이나 실사진 전체 흐름의 성공을 뜻하지 않습니다.

0.1.5는 권한별 요청·설정 열기, 현재 앱 위치 확인, 명시적 권한 초기화 후 재시작 기능을 추가합니다. 사진 앱 일부 요소에서 선택 속성인 `AXDescription`을 읽을 때 발생하는 `AX_READ_FAILED: AXDescription 조회 실패: -25200`도 기존 `AXSubrole`과 같이 해당 속성만 생략하도록 수정했습니다. 설명이 없으면 그 설명을 요구하는 버튼은 선택하지 않습니다. 역할·활성 상태·좌표·크기·화면 트리 조회 실패와 권한·통신 오류는 계속 중단합니다.

0.1.5의 빌드·서명 검증과 Node.js 22.23.1에서 **91개 테스트**를 통과했습니다. 실제 설정 창에서 네 권한 버튼과 초기화 안내가 표시되고, 화면 기록 설정 열기가 해당 시스템 설정 페이지로 이동하며, 실행 중 설정 커맨드로 창이 다시 열리는 것을 확인했습니다. 초기화 명령은 모의 실행으로 대상 제한·부분 실패·진행 중 작업 보호를 검증했습니다. 실제 권한 초기화·승인이나 실사진 1장 재실행은 수행하지 않았습니다.

0.1.4는 `InputImages/`를 기본 입력으로 사용하고, 새 작업 앨범에 복사한 사진을 정확한 ID로 처리하도록 구성합니다. **입력 가져오기부터 실제 Mac 사진 편집·JPEG 내보내기·원본 복귀까지의 전체 흐름은 아직 실사진으로 검증하지 않았습니다.**

0.1.4 도우미의 최종 빌드·서명 검증과 Node.js 22.22.3에서 **89개 테스트**를 통과했습니다. 입력 폴더 탐색·가져오기 식별 검증·앨범 반영 대기·중지와, 합성 JPEG/PNG/TIFF 원본·해시·가져오기 기록 검사를 포함합니다. 도우미 없이 파일 접근을 임시 프로젝트에만 제한한 상태에서도 기본 `plan`이 실행되는 것을 확인했습니다. 해당 도우미의 입력 폴더 기능 응답도 확인했으며 권한을 자동 부여하거나 실제 사진을 가져오지는 않았습니다.

오프라인 테스트는 기본 로직·처리 흐름과 Node 버전 검사·실행 파일의 Node 선택을 검사합니다. 다음 명령은 실제 사진 앱을 조작하지 않습니다. 빌드·오프라인 검증과 실사진 검증은 구분해야 합니다.

```bash
npm test
```

이전 버전에서 Node.js 22.23.1과 26.9.0, 보조 앱 통신, 합성 JPEG의 전체 디코딩·해시 검증, 만료 요청 차단, 설정 창 재열기를 확인했습니다. 이 결과는 새 입력 가져오기 기능의 실사진 검증을 뜻하지 않습니다. 지원 버전 검사는 Node.js 22.12.0 이상을 허용합니다.

도우미의 Swift 코드가 포함된 업데이트 후에는 **보조 앱 종료**를 누르고 설정 커맨드로 다시 빌드해야 새 도우미 코드가 적용됩니다. 권한을 확인한 뒤 1장 테스트로 전체 흐름을 확인하고 일괄 처리를 시작하세요. macOS 업데이트 또는 사진 앱 UI 변경 후에도 한 장 검증을 다시 수행합니다.
