# mac-gyver

맥에서 아이폰 화면을 보며 터치 동작을 기록하고, 타이밍·반복 구간·검사 조건을 편집해 재생하는 데스크톱 앱입니다.

**첫 구현 버전입니다. 아이폰 없이 사용할 수 있는 데모와 실제 기기용 Appium 연결을 제공합니다. 실제 아이폰 제스처와 macOS `.app` 실행 검증은 아직 완료되지 않았습니다.**

## 사진 앨범 반복 자동화

아이폰 사진 앱에서 프레임 재설정·드래그·재생성을 반복하는 전용 스크립트는 [`ios-automation/`](ios-automation/README.md)에 있습니다. 위 데스크톱 앱과 별도로 설치하고 실행합니다.

- [설치 및 실행 안내](ios-automation/README.md): Xcode·Appium 준비, WDA 설치와 7일 서명 갱신, 시작·중지 방법
- [JPEG 내보내기 안내](ios-automation/EDITED-IMAGE-EXPORT.md): 원래 파일명으로 전후 화면 캡처와 결과 JPEG 저장, 저장 검증 후 원본 복원
- [PhotoKit 보조 앱 설치](ios-automation/ExportBridge/README.md): JPEG 모드에 필요한 PhotosExportBridge 빌드·설치

기존 캡처·취소 흐름은 실제 아이폰에서 6장으로 확인했습니다. **0.2.1은 실제 아이폰 한 장의 식별·재생성·JPEG 저장·원본 복원까지 통과했습니다.** JPEG 전체 디코딩·크기·해시와 복원 후 실행 전 이미지 해시 일치를 확인했으며 오프라인 테스트 67개도 통과했습니다. 전체 앨범 JPEG 처리와 강제 중단 후 실기기 복구는 아직입니다. 개인 기기·서명 설정, 사진, 캡처, 로그는 저장소에 포함하지 않습니다.

## Mac 사진 앱 반복 자동화

Mac 사진 앱에서 직접 실행하는 도구는 [`macos-automation/`](macos-automation/README.md)에 있습니다. 0.3.0은 사진 앱의 `Reframe` 앨범을 읽고 `Reframe-날짜시간` 작업 앨범과 독립된 사진 사본을 만들어 처리합니다. 앨범 ID 입력이나 사진 미리 열기는 필요 없습니다. 좌하단 드래그 → 프리뷰 캡처 → 프레임 재생성 → 결과 캡처 → 변경사항 저장 → 전체 크기 JPEG 내보내기·검증을 반복합니다. **작업 앨범과 편집 결과는 그대로 남기며 원본 복귀를 하지 않습니다.** 원본 Reframe 앨범의 사진은 편집하지 않습니다.

`Mac 사진 자동화 설정.command`로 도우미를 빌드하고 권한을 설정합니다. **0.2.1부터 새 Mac은 전체 Xcode나 개발자 계정·인증서 없이 임시 서명으로 빌드**합니다. Node.js와 `xcode-select --install`로 설치하는 Command Line Tools는 필요합니다. 임시 서명으로 코드를 재빌드하면 권한 재승인이 필요할 수 있습니다. 이미 개발자 인증서를 선택해 저장한 Mac은 그 설정을 계속 사용합니다. **1장 테스트도 전체 사진의 사본을 만든 뒤 한 장만 편집**합니다. 다시 1장 테스트를 실행하면 다음 한 장, **시작/이어하기**를 실행하면 같은 앨범의 남은 전체 사진을 처리합니다. 모두 완료하면 종료하고 반복 실행해도 다시 가져오지 않습니다. 새 사본으로 한 장을 테스트할 때는 **Mac 사진 자동화 새 테스트.command**, CLI에서는 `npm start -- --new-run --limit 1`을 사용합니다.

화면 캡처와 JPEG는 같은 날짜·시간 결과 폴더 바로 아래에 원래 파일명을 사용해 저장합니다. iCloud 사진을 사용하면 작업 앨범과 편집도 동기화될 수 있습니다. Node.js는 22.12 이상을 허용하며 현재 PATH의 Node를 우선 사용합니다. 개인 설정·인증서·입력 사진·캡처·로그·빌드된 앱은 저장소에 포함하지 않습니다. 최신 실제 검증 범위와 이전 버전 기록은 [macos-automation README](macos-automation/README.md#검증-범위)를 참고하세요.

설정 창을 열면 Dock과 ⌘Tab에 앱이 표시됩니다. 숨긴 설정 창은 Dock 아이콘·메뉴 막대·앱 재실행·설정 커맨드로 다시 열 수 있습니다. 도우미 업데이트는 설정 창에서 **보조 앱 종료** 후 설정 커맨드를 다시 실행합니다. 재빌드 후에는 권한 상태부터 확인하고 불필요하게 초기화하지 마세요. `npm run plan`은 Reframe 앨범 목록만 조회하며 복사·편집은 하지 않습니다. 0.3.1은 실제 Reframe 20장의 독립 사본 생성과 한 장의 재생성·캡처·JPEG 저장·편집 보존을 확인했습니다. 기존 편집 2장을 포함한 원본 20장의 이미지 해시·편집 상태는 그대로였으며, 나머지 사본 19장의 전체 편집 성공은 아직 검증하지 않았습니다.

## 바로 실행

1. Python **3.11~3.14**가 있는 맥에서 저장소를 내려받습니다.
2. **`Demo.command`를 더블클릭**합니다. 처음에는 프로젝트의 `.venv`에 Python 의존성을 설치합니다.
3. 데모에 연결한 후 미리보기에서 클릭·드래그로 동작을 기록하고 저장·반복·보고서 기능을 확인합니다. 필요하면 `examples/demo_roundtrip.json`을 불러옵니다.

터미널에서도 실행할 수 있습니다. 아래 명령은 저장소 폴더에서 실행합니다.

```bash
bash Demo.command
```

실제 아이폰을 연결하려면 [맥·아이폰 설정 안내](docs/SETUP_MAC.md)를 따라 Xcode와 WDA 서명을 준비하고, 터미널에서 Appium을 켠 뒤 `Start.command`를 실행합니다.

```bash
bash scripts/start_appium.sh
```

다른 터미널 또는 Finder에서:

```bash
bash Start.command
```

Appium은 `127.0.0.1:4723`에서 실행됩니다. Python·Xcode·Node.js와 Apple 서명 계정은 사용자가 준비합니다. 실행 스크립트는 시스템 도구나 계정을 자동으로 설치·변경하지 않습니다.

## 동작 입력과 편집

기본 흐름은 **연결 → 시작 화면 준비 → 기록 시작 → 미리보기 조작 → 기록 종료 → 단계 편집 → 한 번 실행 → 반복 실행**입니다.

| 동작 | 입력하는 방법 | 조절하는 값 |
| --- | --- | --- |
| 탭·더블탭 | 도구 선택 후 미리보기 클릭 | 위치 또는 UI 요소, 동작 후 대기 |
| 길게 누르기 | 위치 클릭 | 누르는 시간 |
| 스와이프·드래그 | 시작점에서 끝점으로 마우스 드래그 | 이동 시간, 이동 전 누름·끝점 유지 시간 |
| 확대·축소 | 중심 위치와 제스처 속성 지정 | 배율·속도 |
| 두 손가락 회전 | 중심 위치와 제스처 속성 지정 | 각도·속도 |
| 대기·검사 | 단계 추가 또는 요소 검사 도구 사용 | 고정 시간, 요소 표시·사라짐, 기준 이미지 비교 |
| 반복 | 연속된 단계를 선택해 반복으로 묶기 | 횟수·회차 사이 대기 |

- `기록 시작 화면을 재생 전 검사`가 켜져 있으면, 재생 전에 처음 기록했던 화면으로 되돌아가야 합니다.
- 기록하는 것은 **맥 앱을 통해 입력한 명령**입니다. 아이폰에서 손가락으로 직접 수행한 동작은 수집하지 않습니다.
- 좌표는 미리보기 여백을 제외한 화면 내 비율로 저장하며, 기기 화면 방향·크기 변화는 실행 전에 확인합니다.
- 실행은 한 번에 하나만 진행합니다. 일시정지·중단 요청은 이미 전송된 기기 명령을 끝낸 뒤 적용될 수 있습니다.
- 단계 JSON을 저장·불러오기할 수 있습니다. 사진 선택 좌표와 UI 요소 이름은 실제 아이폰 화면에 맞게 기록해야 합니다.
- `요소 읽기` 후 UI 요소를 선택해 대상으로 사용하거나, `이미지 영역 검사` 도구로 미리보기에서 비교 영역을 드래그할 수 있습니다.
- 요소 검사와 기준 이미지 비교를 추가해야 원하는 동작을 확인할 수 있습니다. 검사가 없는 실행은 **검사 없음**입니다.

제스처의 목표 시간과 동작 후 대기는 따로 설정합니다. 보고서의 소요 시간은 맥에서 관측한 명령 처리 시간으로, 실제 터치 시각이나 화면 렌더링 성능 측정값이 아닙니다.

## 실행 결과

각 실행은 JSON 결과, HTML 보고서, 필요한 PNG 스크린샷을 남깁니다. 통과·실패·실행 오류·검사 없음·사용자 중단을 구분하고, 실패 지점에서 멈춥니다. 실패한 터치 명령을 자동 재시도하지 않습니다.

기본 결과 폴더는 `~/Library/Application Support/mac-gyver/reports`이며 CLI 실행 시 `--output`으로 바꿀 수 있습니다. 스크린샷과 기준 이미지는 실행한 맥에 저장됩니다. 보고서는 웹 서버 없이 파일로 열 수 있습니다. 스크린샷에는 테스트 화면이 담기므로 공유할 보고서를 직접 확인하세요.

## 명령줄

설치 후 저장소 폴더에서 실행합니다.

```bash
# 환경 진단
.venv/bin/python -m mac_gyver --diagnose

# 창 없이 데모 시나리오 실행
.venv/bin/python -m mac_gyver --demo --run examples/demo_roundtrip.json --output reports

# 실제 아이폰: 사용자 설정 파일의 UDID/서명 정보 사용
.venv/bin/python -m mac_gyver --config device_config.json --run examples/photos_roundtrip.example.json --output reports

# 전체 옵션
.venv/bin/python -m mac_gyver --help
```

`--cycles N`은 준비 단계를 한 번 실행한 뒤 테스트 구간을 N회 반복합니다. `--skip-setup`은 준비 단계를 생략하지만 시작 화면 검사는 유지합니다. CLI 실행 종료 코드는 검사 통과 `0`, 실패·실행 오류 `1`, 검사 없는 완료 `2`, 사용자 중단 `130`입니다.

실기기 예제의 좌표는 시작점일 뿐입니다. **테스트 앨범과 사진을 직접 지정한 뒤 1회부터 실행하세요.** [예제와 JSON 설명](examples/README.md)

## 개발 및 패키징

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest
```

화면 서버가 없는 환경에서 UI 검증을 실행할 때는 `QT_QPA_PLATFORM=offscreen`을 사용할 수 있습니다. 해당 모드는 실제 아이폰이나 macOS 검증을 대신하지 않습니다.

Mac에서 `.app`을 만들려면:

```bash
bash scripts/build_macos.sh
```

결과는 `dist/mac-gyver.app`입니다. 저장소에는 미리 빌드한 `.app`을 포함하지 않습니다. 빌드한 Mac의 아키텍처에 맞는 앱이 생성되며, 타인에게 배포할 때의 Developer ID 서명·공증은 별도 과정입니다. Appium·Xcode·WDA도 별도로 필요합니다.

| 경로 | 내용 |
| --- | --- |
| [설정 안내](docs/SETUP_MAC.md) | 맥 준비, WDA 서명, 실기기 연결, 오류 해결 |
| [검증 기록](docs/VALIDATION.md) | 자동 테스트 86개, 데모·설치 확인, 남은 실기기 확인 |
| [구현 구조](docs/ARCHITECTURE.md) | 입력·엔진·기기·검사·결과 모델 |
| [원래 구현 계획](docs/Plan_iPhone_자동테스트_2026-09-15.md) | 요구사항과 실기기 완료 기준 |
| [예제](examples/README.md) | 데모, 사진 왕복, 제스처, 기기 설정 |
| `src/mac_gyver/` | PySide6 UI, 기록기, 엔진, 기기 백엔드 |
| `tests/` | 핵심 동작과 오류 처리 검증 |
| `scripts/` | 로컬 의존성 설치, Appium 실행, Mac 빌드 |

설치·CLI·Python wheel 빌드와 데모 사진 왕복 3회(검사 12개, PNG 3장 생성)를 Linux 개발 환경에서 확인했습니다. 이는 실제 아이폰 동작이나 macOS 앱 실행 검증이 아닙니다.

기본 의존성은 `pyproject.toml`과 `requirements.txt`에 버전을 고정했습니다. 개발 검증 환경의 Python은 3.12입니다. 사용자의 macOS·Xcode·iOS 조합은 첫 실기기 실행에서 확인해야 합니다.
